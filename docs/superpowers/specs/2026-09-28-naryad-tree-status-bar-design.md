# Строка состояния дерева наряда

## Цель

Вернуть на вкладках «Задание» и «Выполнение» постоянно видимую строку
состояния, которая после выбора узла показывает `Код: {id}`.

## Текущее состояние и причина переработки

Текущая реализация добавляет в общий `BaseTreeTable` проп `statusBar`,
внутреннее состояние `selectedRowId`, функции сборки текста и `tfoot` внутри
прокручиваемой таблицы. При этом `NaryadWorkspacePanel` уже хранит тот же
выбранный идентификатор для загрузки параметров и алгоритма.

Такая схема дублирует состояние, связывает прикладную подпись наряда с общим
табличным компонентом и делает видимость строки зависимой от поведения
`tfoot` в прокручиваемом контейнере. Полная копия компонента для ручного
переноса также регулярно расходится с актуальным `mainComponent`.

## Решение

Полностью удалить API и разметку текущей строки состояния из подготовленной
версии `BaseTreeTable`. В `NaryadWorkspacePanel` разместить отдельную строку
непосредственно под областью дерева, вне её прокрутки.

Единственным источником данных будет существующий `selectedId`, который
`BaseTreeTable` передаёт через `setSelectedId`. Пока узел не выбран, полоса
остаётся видимой без текста. После выбора она показывает `Код: {id}`.

При смене `treeUrl` существующий эффект очищает `selectedId`, поэтому строка,
параметры и алгоритм сбрасываются согласованно.

## Границы изменения

- Строка появляется только в деревьях задания и выполнения.
- Каталог тематических разделов не получает строку состояния.
- Выбор строк, загрузка параметров и алгоритма не меняются.
- Перенос текста, растущая высота строк и многоуровневые заголовки дерева
  сохраняются.
- Новых зависимостей не добавляется.

## Проверка

- Модульный тест функции формирования подписи: пустое значение, числовой и
  строковый идентификаторы.
- Существующие frontend-тесты.
- Production-сборка frontend.
- Ручная проверка вкладок «Задание», «Выполнение» и совместного режима:
  полоса видна постоянно, выбранный код обновляется, таблица прокручивается
  независимо от полосы.
