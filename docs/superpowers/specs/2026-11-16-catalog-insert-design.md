# Вставка из каталога тематических разделов

## Цель

Модалка «Каталог» на карточке наряда перестаёт быть только просмотром: пользователь
выбирает дату выполнения операции, узел каталога и место относительно строки в дереве
задания или выполнения, затем вставляет полный раздел или пустой раздел через существующие
процедуры БД. Дата обязательна: `operlife` и параметры операции зависят от месяца.

## Нецели

- Drag-and-drop из каталога на дерево наряда (отложено, как в `tematic-razdel-notes.md`).
- Модальный `GetHierarchyItem` / `HIERARCHY1` (другой сценарий справочников).
- Замена уже сделанного «Добавить пустой блок» (`*_add_emptyblock`) на панели наряда.
- Изменение DDL процедур в `bd_bur`.

## Контекст Delphi / БД

Источник UX: `old_delphi/formStructNur` + drop/вставка в `CommonNarZadUnit` /
`CommonNarVipUnit`. Процедуры в `bd_bur`:

| Режим | Задание | Выполнение |
|--------|---------|------------|
| Полный раздел (поддерево каталога) | `burnar.zadanie_add_razdel` | `burnar.vipolnenie_add_razdel` |
| Пустой раздел (только выбранный узел) | `burnar.zadanie_add_emp_razdel` | `burnar.vipolnenie_add_emp_razdel` |

Сигнатура: `(nkey, datein, aparent, aprnum, razdel, who, withname)`. Веб вызывает с
`who = null`, `withname = 1`. `razdel` = `id` выбранного узла `tematic_razdel`.

Отличия от Delphi, согласованные для веба:

- добавлен place **после** выбранной строки;
- пустые разделы — **отдельные** кнопки, не пункты внутри меню «Задание»/«Выполнение»;
- дата — date-only в стиле сквозных параметров;
- окно **немодальное**, без затемнения рабочей области.

## UI

### Окно

`CatalogDialog` открывается с `DraggableDialog` в режиме `modeless` (уже есть:
`hideBackdrop`, `disableEnforceFocus`, `pointerEvents: none` на корне, клики только по
Paper). **Общую подложку не ставить** (в отличие от `SkvParamsWindows`): дерево наряда
остаётся кликабельным, чтобы сменить якорь вставки, не закрывая каталог.

Каталог по-прежнему `keepMounted` после первого открытия на карточке (раскрытие/фильтры).

### Дата

Date-only поле в том же визуальном стиле, что дата в сквозных параметрах (`LocalizationProvider`
+ MUI Date Picker, `dd.MM.yyyy`, без часов). По умолчанию — сегодня. Пока дата пуста,
кнопки вставки выключены. На сервер уходит начало суток выбранного дня (локальная дата →
`yyyy-MM-dd'T'00:00:00` или эквивалент timestamp без времени).

### Кнопки

Четыре действия, каждое с меню place (Перед / После / В конец раздела):

1. Добавить в задание (`mode=full`, part=zadanie)
2. Добавить в выполнение (`mode=full`, part=vipolnenie)
3. Пустой раздел → задание (`mode=empty`, part=zadanie)
4. Пустой раздел → выполнение (`mode=empty`, part=vipolnenie)

После успеха дерево целевой части перечитывается; каталог не закрывается.

### Place и якорь

Якорь — выбранная строка **целевой** части (для кнопок задания — дерево задания, для
выполнения — дерево выполнения), даже если открыты обе вкладки.

| Place | Якорь в наряде | `aparent` | `aprnum` |
|--------|----------------|-----------|----------|
| `before` | любая строка | `parent` (или `null` на корне) | `prnum` |
| `after` | любая строка | `parent` (или `null` на корне) | `prnum + 1` |
| `end` | только раздел/блок (`operlifetype` пуст) | `key` блока | `null` (хвост детей) |
| пустое дерево | без якоря | `null` | `1` |

Если якорь — **пустой блок** и place = `before`: диалог как в Delphi —
«внутрь блока» (`aparent = key`, `aprnum = 1`) или «перед блоком» (как обычный `before`).
Отмена диалога ничего не вставляет.

Пункт **«В конец раздела»** disabled, если якорь — операция (не раздел).

### Когда кнопки выключены

Общее:

- нет даты;
- нет выбранного узла каталога;
- целевая часть закрыта;
- нет `defnarvip` (кнопки выполнения);
- мутация уже идёт.

Дополнительно:

- **пустой раздел**: в каталоге выбрана операция (`oper != null`) → вся кнопка disabled
  (`*_add_emp_razdel` для операции ничего не делает);
- **перед** заблокированной строкой выполнения → пункт/действие недоступно
  (текст отказа Delphi: «Нельзя добавлять работы перед заблокированной!»);
- пустое дерево: доступны вставки с корневым слотом; place `end` без якоря не нужен
  (тот же корневой слот).

Отказы процедуры (`Операции необходимо добавлять в основные блоки!`, неприменимость на
дату и т.п.) показывать диалогом с текстом сервера, как у других действий наряда.

## Backend

### API

```http
POST /api/naryady/{id}/zadanie/catalog
POST /api/naryady/{id}/vipolnenie/catalog
```

Тело:

```json
{
  "razdelId": 123,
  "dateIn": "2026-11-16T00:00:00",
  "place": "before | after | end",
  "mode": "full | empty",
  "anchorNodeId": 456
}
```

`anchorNodeId` обязателен, если в части уже есть строки; для пустого дерева — `null`/omit.

Ответ: пустое тело или минимальный ack (как у других `requestAction`); клиент делает reload.

### Сервис

1. Проверить существование наряда и что часть не закрыта.
2. Для `empty` — убедиться, что узел каталога существует и `oper IS NULL`; иначе 400/409.
3. Загрузить структуру части (как clipboard) и вычислить `(aparent, aprnum)` по place.
4. Для выполнения + `before`/`after` на locked — 409 с понятным текстом.
5. `CALL` соответствующей процедуры; сообщения процедуры маппить через
   `NaryadProcedureMessages`.

DDL не меняем: процедуры уже в `bd_bur`
(`procedures/zadanie_add_razdel.txt`, `zadanie_add_emp_razdel`,
`vipolnenie_add_razdel`, `vipolnenie_add_emp_razdel`).

## Frontend wiring

`NaryadPage` передаёт в `CatalogDialog` живые пропсы (не снимок на момент открытия):

- `naryadId`, флаги `hasVipolnenie`, `zadanieClosed`, `vipolnenieClosed`;
- `zadanieAnchor` / `vipolnenieAnchor` (id + признаки блока/locked/`hasChildren`/parent/prnum)
  из текущего выбора и `structure` частей;
- `onInserted(partId)` → reload signal соответствующей вкладки.

Правила доступности и маппинг place — чистые функции рядом с каталогом (как `clipboardRules`),
с тестами на `node:test`.

Пикер даты лучше вынести в маленький переиспользуемый helper/компонент рядом со сквозными
или локально в каталоге с тем же `slotProps`/локалью, но **без** времени.

## Тестирование

- Юнит: place → slot; empty-mode disabled при `oper`; `end` disabled на операции-якоре;
  пустое дерево; пустой блок + before → inside/before.
- Ручная проверка: немодальность (клик по дереву наряда при открытом каталоге меняет якорь);
  вставка в задание и выполнение; смена месяца даты меняет применимость операций (отказ или
  другой `operlife`); пустой раздел только для узла-раздела каталога.

## Риски

- Процедура молча пропускает операции без `operlife` на дату — пользователь может увидеть
  неполный раздел; поведение как в Delphi, отдельно не «чиним».
- Пока `BaseTreeTable` после reload показывает только корни (пакет), раскрытие может сброситься —
  известное ограничение карточки, не блокер этой задачи.
